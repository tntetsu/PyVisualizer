# ADR-008: コード表示のオレンジ（評価中の式）は式にだけ付ける

- ステータス: 採用
- 日付: 2026-11-25

## 背景

コード表示では、評価中の式の範囲がオレンジの背景で表示される（JSVisualizer の `views/code-view`）。コード表示は、トレースのイベントに式の終わりの位置（`end`）があれば、`loc`〜`end` の範囲をオレンジにする。

JS のパーサー（JSInterpreter）は、`end` を式にだけ付けて、文には付けない。一方、Python の AST 変換（`src/engine/parse.js`）は、文を含むすべてのノードに `end` を付けていた。そのため Python 版では次の問題が起きていた。

- 実行した直後（ステップ 0、`Program` に入ったところ）に、ソース全体がオレンジになる
- `for` 文・`if` 文・`def`・`class` などに止まると、そのブロック全体がオレンジになる

公開した直後（2026-11-25）に、利用者の確認で見つかった。

## 利用者に見える例

テストは `tests/adr-examples.test.js`（ADR-008 例1・2）。2 件とも、直す前のコードで失敗することを確かめた。

次のプログラムを実行する。

```python
total = 0
for i in range(2):
    if i > 0:
        total += i
print(total)
```

1. 実行した直後は、コードにオレンジの範囲が表示されない（以前は 1〜5 行目のすべてがオレンジになっていた）
2. 式の単位で最後まで進めても、オレンジになるのは `range(2)`・`i > 0`・`total += i`・`print(total)` のような式だけになる。`for` 文や `if` 文で止まっても、ブロック全体（2〜4 行目や 3〜4 行目）はオレンジにならない

## 決定

- Python の AST でも、JS のパーサーと同じく、文（と `Program`・`except` 節）のノードには `end` を付けない（`STATEMENT_TYPES`）。式のノードには、これまでどおり付ける
- `for` のループ変数（`LoopBinding`）と `except` の行（`ExceptBinding`）のイベントは、これまでどおり `end` を持つ。ループ変数の名前、`except ZeroDivisionError as e` の部分がオレンジになる（ADR-003・ADR-006）
- フロントエンド（JSVisualizer）は変えない

## 結果

- 文で止まったときのコード表示が、JS 版と同じになった。今どの行にいるかは、行のハイライト（青）で示される
- 全 27 サンプル × 全タブ × 5 位置（実行直後・「人」5 回・「式」3 回・「人」15 回・末尾）× ビューとコード表示（とページのエラー）の計 3,267 件の画面の HTML を、直す前と比べた（`scripts/capture-js-dom.mjs` を Python 版のビルド用に変えたもの）
  - ビュー：違いはなかった（実行トレースで 3 件違ったが、配列の図を遅れて描くタイミングによる揺れで、直す前のビルドを 2 回記録しても同じように違った）
  - コード表示：492 件で違い、すべて文で止まったときのオレンジ（1〜24 行分）が消えたもの。オレンジ以外の表示と、式で止まったときのオレンジは変わらない
- マニュアルのスクリーンショットを撮り直した。`code-highlight-line`・`screen-run` は `tmp = arr[j]` の文で止まった画面なので、その文のオレンジがなくなった（説明しているのは行の青と呼び出し元の紫なので、説明文は変えない）
