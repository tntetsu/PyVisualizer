### 2.1 CPython と違う見え方（ADR で決めたもの）

- 集合は入れた順に表示する（CPython はハッシュ値で決まる順）
- ジェネレーター式は、その場で全部計算した list として扱う
- PyVisualizer が出す例外のメッセージは日本語の説明（型の名前は同じ。`raise` で投げた例外のメッセージは書いたとおり）
- インスタンスの既定の表示（`<__main__.Dog object>`）にアドレスを付けない
- `input()` は画面の入力欄の行を読み、端末と同じく読んだ行をコンソールに表示する
- `import` できるのは `math` だけ

### 2.2 ステップ実行

`for` の各回（ADR-003）と同じく、次の 2 か所でも「人」のステップが止まる。

- 内包表記の各回（`LoopBinding`）
- `except` で例外を捕まえたところ（`ExceptBinding`）

特殊メソッド（`__str__`・`__eq__` など）は、ユーザーのコードとしてトレースに記録されるので、ステップ実行で中に入れる。

### 2.3 フロントエンド（JSVisualizer の作業ブランチ）

入力欄（`components/input-panel.js`）を足した。言語プロファイルが `supportsInput: true` のときだけ作り、実行時に `adapter.load(source, { stdin })` で渡す（JSVisualizer の ADR-055 に追記）。JS 版の画面は変わらないことを確かめた。

- JS 版では入力欄が 0 個で、ソースペインの HTML も変わらない
- 7 本のサンプル・題材 × 全タブ × 5 位置の画面の HTML が main と一致した

## 3. 比較テストで分かったことと対処

CPython との変数の状態の比較テストを、Phase 5 の機能に合わせて直した（`tests/line-state.test.js`・`tests/tools/trace_states.py`）。

| 分かったこと | 対処 |
|---|---|
| CPython 3.12 は内包表記を呼び出し元のフレームの中で実行する（PEP 709）。そのため、途中の変数（ループ変数や作りかけの値）が一時的に見える | 両者とも、内包表記の中とジェネレーター式のフレームではチェックしない |
| 集合の順序はハッシュ値で決まる | 要素を並べ替えて比べる |
| エンジンが投げる例外のメッセージは日本語 | 例外は型だけで比べる |
| CPython の tracer がユーザーの `__repr__` を呼ぶと、`__init__` の途中で失敗して例外がプログラムに漏れた | インスタンスは、ユーザーのコードを呼ばずに属性から作った表記で比べる |
| `sorted` が `__lt__` を呼ぶ順序・回数は CPython と違う | 出力だけを比べる（`output_` で始まるテストケース） |
| `max`・`min`・比較の演算子が、CPython より多く特殊メソッドを呼んでいた | CPython と同じ手順（その演算子の特殊メソッド → 反射した側）にした。呼ぶ回数も一致する |
| 関数の変数の順序が CPython と違った（`*args` の位置） | CPython と同じ順（位置引数 → キーワード専用引数 → `*args` → `**kwargs`）で作る |
| 例3（ADR-006）を書いてテストを足したら、`except` で捕まえたところで「人」のステップが止まっていなかった | `ExceptBinding` を止まる所に加えた（ADR を書いてからテストを足すことで、実装の漏れが見つかった） |
